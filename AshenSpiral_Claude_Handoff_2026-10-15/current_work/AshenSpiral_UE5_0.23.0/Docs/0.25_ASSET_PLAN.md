# 0.25 asset plan (final draft, 2026-10-19)

Plan only. Nothing has been imported or built. It follows from `Docs/0.25_ASSET_RESEARCH.md`; read that for the
inventory and the reasons. Gate 0 and Gate 1 below need Josue before any work starts.

## Ground rules

- Never buy anything. Only assets already in the vault, and only once their licence is confirmed commercial-safe.
- Import is allowed only through the editor commandlet, import-only (standing permission). No in-engine playtests by me.
- Per item: clean unity and non-unity editor builds, `Tests/run_tests.py` exit 0, crash-safety review. Everything
  visible is UNVERIFIED until Josue and P2 look.
- Texture budget is part of the plan: cap imports at 2048 (1024 for small props), no 16k or 8k source textures in
  `Content`. Only the chosen meshes are imported, never whole packs.
- New content goes under `Content/Art/Imported/<Pack>/`. Each pack gets a line in `Docs/CREDITS.md` (seller, listing,
  licence) before it is committed.

## Gate 0: licence (Josue, before anything)

For each pack used, open its Fab library page and confirm commercial use is allowed and whether attribution is
required. Packs in this plan: Dragon Cave, Paragon animations, Molten Face Hammer, Concrete column, Game Animation
Sample. Anything that fails drops out and its phase is skipped. Record the answer in `Docs/CREDITS.md`.

## Gate 1: bugs first (separate fix batch, not asset work)

Art must not land on these systems while they are broken, because a visual or collision mismatch would hide the
cause: P2 invisible walls, endless cover desync, flying enemies leaving the map in normal mode, unlit sigils and
vault. This plan assumes a fix batch runs first. Phase A may start in parallel only for work that does not touch
moving blocks or cover (see below).

## Phases (in order)

### A. Pipeline and the hammer (smallest, proves the import path)
1. Write a commandlet import script (Python, in `Tools/`) that imports a named list of files with a texture cap, a
   target folder, and a log. Import the Molten Face Hammer as `SM_MoltenHammer` at 1024 textures.
2. Use it for the elite hammer enemy and define a head socket; the slam hit location comes from that socket
   (playtest: the slam should use the head of the hammer). Files: `ASEnemy.cpp` (hit shape), the elite kit in
   `ASEnemyRules.h`, a native test for the shape.
Size: small. Risk: low.

### B. Arena blocks and the concrete look
1. Crop and downscale one tile from the Concrete column textures (Blender or script, outside the engine) to 2048
   albedo and normal. Build `M_ArenaConcrete` and apply it to the existing procedural blocks. No mesh swap, so the
   server-decided collision stays exactly as it is.
2. Optional variants: Dragon Cave `SM_StoneWall01-04`, `SM_StoneworksStone01-03` as extra block looks, with simple
   box collision generated in code, not the pack's own.
Files: `ASWorld.cpp` (material only), a new material asset. Size: small. Risk: low once Gate 1 is done; this phase
waits for the cover fixes.

### C. Endless arena skin and decay stages
1. Import about 25 Dragon Cave meshes: pillars (`SM_StoneworksPillar01-04`, `SM_LargePillar01-02`), rocks
   (`SM_LargeRock01-07`), dead trees, rubble, bridge pieces, skulls and skeletons, with textures capped at 2k.
2. Dress the endless arena in three stages tied to the existing sky bands (waves 1-20, 21-50, 50+): clean stone and
   greenery, then dead trees and rubble, then skulls, skeletons and inferno rocks, with the blood treatment on top.
   Decor is visual only, with no collision, and is placed away from the walkable play space so nothing can block
   movement or shots. Anything that must block gets a code-made box, as now.
3. Chest dressing from the coin, cup, jewel and treasure-pile meshes.
Files: `ASWorld.cpp` / endless layout code, `ASGameMode.cpp` for the stage swap (reuse the sky-band logic), a native
test that stage selection by wave is right. Size: medium. Risk: medium (frame cost and the 5 GB source; mitigated by
the import cap and a mesh budget of about 600 decor instances).

### D. Enemy animation from the Paragon pack
1. Pick clips only, not heroes: `minionsManny` for grunts, and attack sets from Wraith, Countess, Narbash, Serath and
   Phase for the humanoid kinds. Import about 40 clips total, retargeted onto the existing Manny rig that the baked
   death curves already use.
2. Map clips to the 0.24 ability ids through a data table next to `ASEnemyAbilities`. The Tier 0 pose tracks stay as the
   fallback whenever a clip is missing, so nothing regresses.
Files: the ability table, `ASEnemyPose`/`ASEnemy` playback glue, a native test that every ability id resolves to a
clip or the fallback. Size: large. Risk: medium (skeleton match is unconfirmed until the first import; the first
import is a spike on one clip). Only after Gate 0.

### E. Audio
Foley footsteps from the Game Animation Sample (about 20 waves) and, if the licence allows, a monster cue for the
louder boss roar. Wire through the existing audio manifest (`Docs/AUDIO_MANIFEST_0.24.md`). The roar's visual half is
code and lives in the fix batch. Size: small. Risk: low.
